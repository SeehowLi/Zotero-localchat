# Zotero-localchat

把已登录的 ChatGPT Windows App 接入 Zotero：一边阅读论文，一边在独立侧栏提问；每篇论文在你选择的 ChatGPT 聊天项目中沿用自己的对话。首次使用推荐 `zotero-paper`，也支持自定义名称和已有的 `Paper`。

**当前发布：0.4.12，Windows 预览版。** [下载发布包](https://github.com/SeehowLi/Zotero-localchat/releases/tag/v0.4.12) · [更新记录](CHANGELOG.md) · [验证记录](docs/VALIDATION.md) · [贡献者](CONTRIBUTORS.md)

这是独立实验项目，与 OpenAI 和 Zotero 无隶属关系。插件依赖桌面 App 的页面结构，App 更新后可能需要调整适配器。

## 你需要准备什么

| 项目 | 要求 |
| --- | --- |
| 系统 | Windows x64；macOS、Linux 暂不支持。 |
| Zotero | 当前仅适配 Zotero 10，已验证 10.0.3 beta；Zotero 7/8 暂不支持。 |
| OpenAI 桌面 App | 含 ChatGPT 聊天界面的 Windows App，已验证版本 26.915.4065，使用中文界面。启用脚本查找 `OpenAI.Codex` 或 `OpenAI.ChatGPT` 应用包及其 `app/ChatGPT.exe`。其他版本不保证兼容。 |
| ChatGPT 账号 | 已在桌面 App 登录，并能正常发送聊天消息。可选模型及文件限制由当前账号决定。 |
| Node.js | 22 或更高版本，已验证 Node.js 24；可从 [Node.js 官网](https://nodejs.org/) 安装。 |
| 论文 | Zotero 中已有可在本机打开的 PDF。只有云端条目而没有下载 PDF 时，先下载附件。 |

**不需要 API Key，不需要再登录一个网页，也不需要复制 Cookie。** Zotero 只连接本机中转，ChatGPT App 沿用自己的网络和代理设置。如果 App 本身无法联网，插件也无法替它生成回答。

## 首次安装：按顺序完成这五步

### 1. 下载并解压完整包

进入 [0.4.12 发布页面](https://github.com/SeehowLi/Zotero-localchat/releases/tag/v0.4.12)，在 **Assets** 中下载：

- **`Zotero-localchat-0.4.12-windows.zip`：首次安装和升级都推荐使用这个完整包。**
- `Zotero-localchat-0.4.12.xpi`：只有 Zotero 插件部分，不能单独提供本地服务和聊天前端。
- `SHA256SUMS.txt`：可选，用于核对下载文件的 SHA-256。

不要把 GitHub 自动生成的 **Source code (zip)** 当作 Windows 安装包；源码需要自行构建辅助程序。

将完整包解压到一个长期保留的目录，例如 `D:\Tools\Zotero-localchat`。不要在压缩包预览窗口里直接运行文件，也不要只复制 XPI 后删除其余文件。

解压后的目录应包含：

```text
Zotero-localchat-0.4.12.xpi
Start-LocalChat.cmd
Stop-LocalChat.cmd
scripts\
bridge\
bin\LocalChatWindow.exe
README.md
```

安装 Node.js 后，新开一个 PowerShell 窗口输入：

```powershell
node --version
```

显示 `v22...` 或更高版本即可。若提示找不到 `node`，先完成 Node.js 安装，再重新打开终端。

### 2. 准备 ChatGPT 账号和聊天项目

1. 打开已登录的桌面 App，进入 **ChatGPT 聊天界面**。
2. 在聊天项目中创建 **`zotero-paper`**，也可以用自己的名称。稍后在插件的首次使用引导中填写相同名称，大小写和拼写保持一致。
3. 如果 App 同时有 Codex 工作项目，注意这里要创建的是 **ChatGPT 的聊天项目**。
4. 如果已经有 `Paper`，直接使用现有项目，不必再建一个。已有论文关联的旧配置会自动沿用 `Paper`。
5. 确认 App 内普通聊天可以正常发送消息。

也可以等安装好插件后，按首次使用引导点击“打开 / 切换到 App”，再完成项目创建。当前版本由你在 App 中手动创建项目，插件负责检查、识别和记住所选项目。

### 3. 创建并使用专用 App 快捷方式

在刚才解压的目录打开 PowerShell，然后执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\scripts\Enable-App-Bridge.ps1"
```

例如，要先进入上面的示例目录：

```powershell
Set-Location -LiteralPath 'D:\Tools\Zotero-localchat'
powershell -NoProfile -ExecutionPolicy Bypass -File ".\scripts\Enable-App-Bridge.ps1"
```

脚本会在桌面创建 **`ChatGPT - Local Chat`** 快捷方式。它只创建快捷方式，不会替你退出 App，也不会退出账号。

随后：

1. 在 ChatGPT App 的菜单中选择退出，**完全退出 App**；只关闭窗口可能仍在后台运行。
2. 使用新建的 **ChatGPT - Local Chat** 快捷方式重新打开 App。
3. 保持登录状态，不需要重新登录或退出账号。

专用快捷方式会开启 `127.0.0.1:23129` 本地连接端口。第一次设置完成后，日常也要通过这个快捷方式启动 App。通常无需管理员权限；上述执行策略只用于这次脚本运行，不要求修改全局策略。

Zotero 自动管理的是本地中转进程，不会强行退出或重启 ChatGPT。App 通过专用快捷方式启动且连接端口可用后会自动连接；仅有普通 App 进程仍不足以开放本地连接。App 中途退出后，侧栏会保留已显示的内容，重新打开 App 后点击“重连”；不会重复发送消息。

### 可选：沿用开始菜单中的 ChatGPT 图标

0.4.12 完整发布包已包含此安装脚本，可直接在解压目录运行。

如果希望继续使用开始菜单中的 **ChatGPT** 图标，可先运行可选脚本：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\scripts\Install-StartMenu-Entry.ps1"
```

它会在 `%USERPROFILE%\.zotero-localchat\app-launcher` 创建同名、官方图标的 `ChatGPT.lnk`，复用已安装的 App 和登录状态。右键这个快捷方式选择“固定到开始”，再取消原商店入口的固定；不要卸载 App。新入口每次启动会查找该应用包的当前安装路径，自动附带本地连接参数。可以用同一脚本的 `-VerifyOnly` 参数校验入口，不会启动或退出 App。

如果 App 已经按旧方式运行，首次更换入口后需要完全退出一次，再点击新的开始菜单固定图标。该入口不会强制关闭 App，也不会替换 App 安装文件。未更换的商店入口、其他任务栏图标或 Windows 自启动入口不自动继承参数。

### 4. 登记本地服务（只需运行一次）

在解压目录中双击 **`Start-LocalChat.cmd`**。

- 启动成功时命令窗口通常会自动关闭，后台服务继续运行。
- 想查看输出，可以在该目录的 PowerShell 中执行下面的命令：

```powershell
node .\scripts\start.cjs
```

提示“Local Chat 已启动”或“Local Chat 已运行”即表示本地服务可用。服务使用 `127.0.0.1:23128`；不需要打开浏览器。

这一步会登记本机 Node.js 和完整包的位置。以后打开 Zotero，插件会自动启动本地服务；如果服务中途退出，点击“论文对话”或“重新连接”也会自动恢复。最后一个已连接的 Zotero 进程退出后，服务会退出。无需再手动运行启动脚本，也不会注册 Windows 开机启动。

请保留完整包目录；移动目录或升级完整包后，先运行新目录中的 Start-LocalChat.cmd 一次更新位置。只有 XPI、没有登记完整包时，侧栏会给出首次安装提示。

### 5. 在 Zotero 安装 XPI

1. 打开 Zotero。
2. 进入 **工具 → 插件**（英文界面为 **Tools → Plugins**）。
3. 点击插件管理器右上角的齿轮。
4. 选择 **从文件安装插件 / Install Plugin From File…**。
5. 选择完整包中的 **`Zotero-localchat-0.4.12.xpi`**，确认安装。
6. 检查 **Zotero-localchat** 出现在已启用列表中。
7. 打开一篇 PDF，点击阅读器右侧竖栏中的 **ChatGPT 图标**。

也可使用阅读工具栏的 **Local Chat** 按钮，或快捷键 **Ctrl＋Alt＋M**。如果安装前已经打开的阅读页没有出现新入口，先用快捷键；仍未显示时重开该阅读标签页，必要时重启 Zotero。

首次尝试建议使用独立 Zotero 配置或非敏感论文。插件无需替换论文库，也无需复制其他配置的数据库。

## 首次打开：检查 App 并选择聊天项目

安装好插件并启动本地服务后，第一次展开 Local Chat，会先检查本机 App：

- **App 尚未打开**：点击“打开 / 切换到 App”，通过专用快捷方式打开它。
- **App 已打开，但连接未启用**：完全退出 App，再通过 `ChatGPT - Local Chat` 快捷方式启动。插件不会强制关闭你的 App。
- **已连接**：进入项目选择步骤。

在引导中按顺序操作：

1. 点击 **打开 / 切换到 App**，进入 App 的 **ChatGPT 聊天**；如果当前是 Codex，请先切换。
2. 创建 `zotero-paper` 聊天项目，或使用现有的 `Paper` / 自定义项目。让该项目显示在 App 侧栏中。
3. 回到 Zotero，点击 **重新检查**，在“聊天项目名称”中填写或选择实际名称。
4. 点击 **使用这个项目**。插件确认同名项目唯一存在后保存选择，进入聊天侧栏。

识别基于 App 当前侧栏的项目名称，不能用 Codex 工作项目代替 ChatGPT 聊天项目。同名项目不唯一、项目尚未显示或 App 尚未就绪时，不会猜测选择；请先在 App 中整理或展开项目后重试。

检查与选择项目不会发送消息或上传 PDF。选择保存在 `%USERPROFILE%\.zotero-localchat\settings.json`；以后正常打开直接进入聊天。已有 `Paper` 论文关联的用户会自动继承原项目，无需重新设置或上传。已有对话关联时，插件会阻止改用另一个项目，以免原论文错误地对应到新项目。

需要重新查看选择时，点击右上角 **◐ → 聊天项目…**。如果还没有建立论文或空白对话关联，可以改选项目；否则继续使用原项目。

只有你主动点击首次引导里的“打开 / 切换到 App”才会把 App 切到前面；日常发送在后台进行。首次建立后台连接时仍可能短暂出现 App 初始化窗口。

## 第一次验证是否安装成功

打开 PDF 并展开 Local Chat 后，依次确认：

1. 聊天页上方显示当前论文标题。
2. 输入框下方能看到模型名称及账号支持的推理强度控件。
3. 未提问时显示“首次发送时附上 PDF”等提示，**仅打开面板不会上传论文或发送问题**。
4. 选择一篇你愿意交给 ChatGPT 的论文，输入一个问题，例如“请概括这篇论文的研究问题和贡献”，按回车发送。
5. 提问应立即出现在聊天记录中，输入框随即清空；首次发送会先上传该 PDF，再等待 App 回答。
6. 在同一篇论文里继续追问，应沿用原对话和已上传文件。

上传附件、ChatGPT 服务端排队、模型思考和生成仍然需要时间。本地增量传输不等于消除模型的首次回答等待。

## 同名论文与跨设备续聊

打开论文时，若本机还没有聊天关联，插件会在所选 ChatGPT 项目中查找唯一的同名聊天，恢复历史并保存云端聊天 ID；已有 ID 关联优先保留。后续提问继续写入这个云端聊天。另一台设备使用同一账号、同一项目和新版完整包，重开论文对话或点击重连后读取 App 已同步的内容。

“新聊天”仍创建独立空白聊天。同名结果不唯一时不会自动关联或新建；请在 App 中区分聊天标题后重试。详见[历史恢复与跨设备升级](docs/HISTORY-SYNC.md)。

## 日常怎么使用

### 每天启动

1. 用桌面 **ChatGPT - Local Chat** 快捷方式打开 App。
2. 双击完整包目录里的 **Start-LocalChat.cmd**。
3. 打开 Zotero 和 PDF，点击右侧 ChatGPT 图标。

App 和服务已经运行时，不需要每次提问都重复启动。服务重启后，在 Zotero 上方点击 **论文对话**，或者重新点击 ChatGPT 图标，刷新本机连接。

首次建立专用后台页面时，App 可能短暂出现一个新窗口，然后隐藏。连接建立后复用隐藏页面，正常提问不需要来回切换前台 App。

### 询问当前论文

- 点击 **论文对话**，输入问题后发送。
- **Enter** 发送；**Shift＋Enter** 换行。
- 首次论文问题上传 PDF，后续沿用同一篇论文的聊天；对话保存在所选 ChatGPT 聊天项目中，并尝试按论文标题命名。
- 选中 PDF 中一段文字，在选择弹层中点击 **问 Local Chat**，选中文字会带入输入框，供你编辑后发送。
- **选中文字和打开侧栏都不会自动发送**，仍需你确认提问。

### 空白聊天与新增对话

- 点击面板上方的 **空白聊天**，开始不附带论文 PDF 的聊天。
- 聊天页右上角的 **新聊天** 同样用于开始新的空白对话；它不会默认重新上传当前论文。
- 想返回论文原来的对话，点击上方 **论文对话**。

### 选择模型与推理强度

- 点击输入框下方的模型名称选择可用模型。
- 点击旁边的推理强度按钮，使用滑条、方向键或滚轮调整；拖动时预览，松开后同步到 App。
- 具体名称和档位来自当前账号及模型，可能包括“即时 / 中 / 高 / 极高 / Pro”，不是每个模型都有全部选项。
- 设置未确认时不会用不确定的配置发送消息；看到“未同步”时请重新选择或点击 **重连**。

### 后续追加文件

- 把文件拖进聊天区域，或点击输入框下方的 **＋**。
- 文件会先出现在待发送附件列表中；输入问题并点击发送后，才交给 ChatGPT。
- 点击附件上的 **×** 可以移除待发送文件。
- 同一篇论文可继续追加其他文件，不需要新建对话。
- 本插件对后续附件的限制：单文件最多 **64 MB**，每次最多 **8 个**，所有待发送附件合计最多 **128 MB**。ChatGPT 账号还可能有自己的文件类型、额度和大小限制。
- 首次从 Zotero 自动附带的 PDF 走单独路径，本机检查上限为 **512 MB**；能否被 ChatGPT 接收仍取决于账号与服务限制。

### 阅读回复与提问导航

- 提问有独立底色、边框和“你的提问 · 编号”，回答保留标题、列表、引用、代码、表格及公式。
- 发送时只定位一次到本轮问题；后续内容在下方继续更新，页面不会自动追着新内容向下滚。
- 右侧数字栏可直接跳到对应提问；点击顶部 **☰** 展开问题摘要列表。
- 点击 **最新回复** 只跳转一次，不会重新开启自动跟随。
- 等待回复时可以继续编辑下一条草稿；上一条完成后不会清除新草稿。

### 主题、字号与侧栏大小

- 点击聊天页右上角 **◐ 外观设置**，选择 **明亮 / 黑暗 / 跟随 Zotero**，选择会自动保存。
- “跟随 Zotero”实时同步 Zotero 自身的主题，不需要切换系统主题。
- **Ctrl＋滚轮** 调整聊天字号；**Ctrl＋0** 或点击底部百分比恢复默认。
- 拖动 Zotero 的侧栏分隔条改变宽度，内容会重新排版。
- 点击上方 **论文信息**，或右侧原生信息/笔记图标，返回 Zotero 原生面板。Local Chat 与论文信息不共享滚动区域。

## 已有用户如何升级到 0.4.12

**请同时更新完整 Windows 包和 XPI。** 自动更新 XPI 不能替换旧目录里的本地前端文件。

1. 等当前回答完成，保留好尚未提交的内容。
2. 在旧目录双击 **Stop-LocalChat.cmd**。如果提示聊天仍在进行，等待完成后再停止。
3. 下载并解压新的 **Zotero-localchat-0.4.12-windows.zip** 到固定目录。可以使用新的版本目录，便于保留旧版作为回退。
4. 在**新目录**运行 **Start-LocalChat.cmd**，登记新版位置并启动服务，避免旧目录服务继续占用端口。
5. 在 Zotero 插件管理器中从文件安装新的 **Zotero-localchat-0.4.12.xpi**，让插件接管新版服务。
6. 在 Zotero 点击 **论文对话**或右侧 ChatGPT 图标，重新加载聊天页。

不要删除 `%USERPROFILE%\.zotero-localchat`，那里保存了论文与对话的关联。插件保留原有 ID，升级会原位替换；通常不需要重新上传已关联论文或重建 `Paper`。

0.4.11 起使用这个共享用户目录，避开 Windows 商店应用对 AppData 的文件隔离。首次运行新包会从旧 `%LOCALAPPDATA%\ZoteroLocalChat` 迁移可读取的论文关联和项目设置，已有新配置不会被覆盖。旧目录暂时保留，确认关联正常前不要删除。

App 自身更新后，如果专用快捷方式失效，重新执行新包中的 `Enable-App-Bridge.ps1` 生成快捷方式，再完全退出 App 并通过新快捷方式打开。

## 常见问题

| 现象 | 处理方式 |
| --- | --- |
| `node` 不是可识别的命令 | 安装 Node.js 22 或更高版本，然后重新打开 PowerShell。 |
| 提示未找到 ChatGPT App / 找不到可识别的 ChatGPT.exe | 当前安装不符合适配脚本的应用包结构。核对上面的已验证版本；网页版不能代替该桌面 App。 |
| 侧栏提示本地服务未启动 | 从完整包目录运行 Start-LocalChat.cmd。不要只安装 XPI。 |
| 发送按钮不可用 / 无法连接 App | 确认 App 已完全退出过，并从 ChatGPT - Local Chat 快捷方式启动；点击聊天页“重连”。 |
| 模型列表为空或设置未同步 | 确认 App 处于 ChatGPT 聊天环境，所选项目是聊天项目；点击“重连”。App 更新可能需要新版适配器。 |
| 首次引导找不到项目 | 在 App 的 ChatGPT 聊天中创建或展开该项目，确认名称完全一致且没有重名，再点击“重新检查”。不要选择 Codex 工作项目。 |
| 端口 23128 被占用 | 若是旧版 Local Chat，先用旧目录 Stop-LocalChat.cmd 停止。不要随意结束其他程序进程或更改全局代理。 |
| 服务重启后提示连接凭据失效 | 点击 Zotero 上方“论文对话”或重新点击 ChatGPT 图标，让插件读取新的本机地址。 |
| 提示没有 PDF / PDF 不在本机 | 先在 Zotero 下载并打开 PDF 附件；没有 PDF 时使用“空白聊天”。 |
| 后续附件提示已过期 | 重新添加文件。服务重启后，先前待发送附件需要重新加入。 |
| 发送后断线或状态未确认 | 不要重复提交。点击“重连”核对原聊天；未确认完成时保留待恢复消息，不自动重发。 |
| 找不到原 Paper 会话 | 保留插件对应的原聊天及项目；可在 App 中打开该会话一次后重连。不要为修复连接而删除原会话。 |
| 输入框已清空，但回答还没出现 | 清空表示问题已进入本地发送流程，不代表 ChatGPT 已完成处理。查看状态提示；首次 PDF 上传、模型思考可能需要等待。 |
| 下载后双击没有反应 | 确认已完整解压、Node.js 可用。在发布目录执行 `node .\scripts\start.cjs` 查看具体错误。 |

## 停止、卸载和保留数据

- 暂停使用：运行 **Stop-LocalChat.cmd**。它只停止本机服务，不会退出 App 或删除云端聊天。
- 禁用插件：在 Zotero 的 **工具 → 插件** 中关闭 Zotero-localchat。
- 卸载插件：在该插件的选项菜单中移除。论文库仍由 Zotero 管理。
- 不再使用本地 App 连接：完全退出 App，然后使用原来的普通快捷方式启动。专用快捷方式可自行删除。
- 卸载不等于删除 ChatGPT 中的聊天或文件；这些仍按账号设置保留。

## 数据与本机连接

```text
Zotero 侧栏 ── 127.0.0.1:23128 ── 本机 Node 中转
                                      │ 页面事件 / 文本 / 附件
                               127.0.0.1:23129
                                      │
                          已登录 ChatGPT App → ChatGPT 服务
```

- 服务仅监听回环地址，并验证随机连接令牌、Host 和 Origin。令牌不写入服务日志。
- App 的本地调试端口可以控制已登录页面，仅应在可信本机使用，不要暴露到局域网或互联网。
- `%USERPROFILE%\.zotero-localchat` 保存项目名称、服务启动位置、论文关联、后台窗口标识和临时附件；输入草稿、待确认消息备份、字号与主题保存在本机侧栏存储。
- 后续附件仅在点击发送后交给 App；已发送附件的本机暂存副本会删除，异常遗留副本在后续启动时按 24 小时期限制清理。
- 发布包和仓库不包含真实论文、聊天记录、账号或本机连接令牌。

## 从源码构建

普通用户优先下载 Windows 完整包。开发者需要 Windows x64、Node.js 22+，以及 Windows 的 .NET Framework 编译器；自动化浏览器测试还需要 Microsoft Edge。

```powershell
git clone https://github.com/SeehowLi/Zotero-localchat.git
Set-Location -LiteralPath '.\Zotero-localchat'
npm test
powershell -NoProfile -ExecutionPolicy Bypass -File '.\scripts\package.ps1'
```

无需安装 npm 依赖。打包脚本会编译 `bin/LocalChatWindow.exe`，然后在 `dist/` 生成 XPI 和 Windows 完整包。

`addon/` 为 Zotero 插件；`bridge/` 为本机服务及侧栏；`native/` 为隐藏受管 App 窗口的辅助程序；`tests/` 为回归测试。自动测试使用独立本地页面和合成数据，不访问真实账号。真实环境验证与性能范围见 [验证记录](docs/VALIDATION.md)。
